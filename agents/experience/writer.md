# Writer 经验池

每次完成任务后记录经验教训，供后续写作参考。

## 模板

```
### yyyy-MM-dd | [文章类型] | [主题]

**做得好的地方：**
- 

**遇到的问题：**
- 

**改进措施：**
- 

**下次注意：**
- 

### 2026-07-11 | 技术解读 | 大模型能力突破与效率革命

**做得好的地方：**
- 以"效率革命"为主线串联三篇不同来源的素材（GPT数学证明、Claude代码重写、GPS训练优化），形成统一的叙事逻辑，避免了素材堆砌
- 技术解读做到了"由浅入深"：先用数据/故事吸引注意，再展开技术细节（如用"账本"比喻PPM的独立建模，用"导航员"比喻GPS的角色）
- 三个段落之间用"如果说……那么……"做过渡，结构清晰，读者不会迷失
- 结尾金句"算力总有上限，但效率没有天花板"提炼了全文核心，具有传播潜力

**遇到的问题：**
- 初稿中"700个字符"与标题中"700词"表述不一致（原素材标题与正文本身存在差异），第1轮审稿发现后统一为"700词"
- 敏感词检测报告27个匹配项，但均为技术语境下的正常用词（如"独立""安全""审查"等），无需修改——说明对技术类文章，敏感词工具需人工复核上下文
- 第二节开头"Bun，这个曾在前端圈掀起波澜…"一句话过长，第2轮审稿时拆分为两句，更适配手机阅读

**改进措施：**
- 交叉引用不同素材时，注意数字的一致性（如素材标题和正文可能不一致，以更可靠的来源为准）
- 长句拆分是公众号写作的常态校对项，每轮审稿都应关注段落句长
- 结尾金句应提前在文中埋下伏笔，而非突兀出现——本轮"三条主线"段落自然引出最终判断，收束效果好

**下次注意：**
- 技术解读类文章可以进一步增加类比和可视化描述的密度
- 涉及三方以上素材时，开头用并列结构（"第一件、第二件、第三件"）清晰高效，值得复用
```
